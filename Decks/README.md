# Sentient campaign deck

The presentation has sixteen slides: an opening cover, twelve slides condensed from the supplied campaign brief, the approved accounts and promotional-post examples, and a dark closing slide with the Sentient logo centred in neon lime. The brief slides use one idea per slide, a short headline and a visual composition (a monumental metric, flow, funnel, comparison, timeline, equation or loop) instead of paragraphs. The brief's conditions — follower overlap, CPM guarantee terms and paid-media requirements — stay as footnotes.

The deck has its own layouts. Titles and body copy use system Helvetica; Sentient's Lovelo Black display face sets the cover, metrics, numerals and keywords. The cover reuses the website's 3D Sentient emblem (`site/src/scene.mjs`), loaded only when the cover is shown; no other website scenes or animations are used. The founders photographs are the authorised Louis Gleeson and Ivan portraits, used as background-free cutouts (`site/public/assets/founders/`) made locally with Apple Vision and aligned to the same face size and eye line, so the founders slide shows them whole at any screen size: each body is clipped to a lime circle while the head rises out above it. The accounts slide uses four current SentientDash avatars and the approved follower snapshots. The promotional slide shows the complete covers of the two approved English-language posts, with separate likes and comments and links to Instagram. Those six assets are stored in `site/public/assets/decks/campaign-deck/`; approved source IDs and recorded figures are in `campaign-deck-sources.json`. Slides alternate dark, paper and acid-green surfaces.

Every slide shares one master grid: identical viewport dimensions and margins, fixed eyebrow and page-number anchors, and one title font and starting position. A common title band reserves the longest heading across the deck (the cover sets its own headline and is excluded). The body fills the workspace below it. On screens wider than a phone the layout always spans the full workspace while `fit.mjs` adapts only the type scale (the container that `cqw` units refer to): it shrinks on wide, short screens and grows up to 20% where height is left over, and treats any word wider than its box as not fitting, so words never break mid-word. Printed pages share the same 16:9 dimensions and anchors. Every editable text node declares its field name in `player.mjs`. The two additions use new stable slide IDs so saved text on the fourteen existing slides remains attached to its original content. The account is always written `@chatgptricks`, its real Instagram handle; the editor corrects the older `chatpgtricks` typo in saved copy when it is shown.

In edit mode the accounts slide shows a dropdown on each avatar listing every Sentient-owned account with a recorded follower count (the deck's own snapshots first, then the website catalogue); choosing one sets the avatar and handle and reads that account's exact latest follower count from SentientDash; all four counts also refresh automatically when edit mode starts, and an "Update followers" button repeats it. The counts come from the same `account_snapshots` readings as the SentientDash Tracker; press Done to save them for viewers. Each card keeps the date of its count (`account-N-asof`), and the note shows the date or range. Each promotional post has a link field: pasting an Instagram post or reel link looks it up in SentientDash through the deck Worker and fills the cover, account, title (from the caption's first line, still editable), likes, comments and date with the recorded data; clearing it restores the original post. `pickers.mjs` owns both controls. Choices are saved as hidden editor fields (`account-N-id`, `post-N-url`, `post-N-source`), so they persist and revert like text. See `comments-api/README.md` for the lookup and cover routes and the SentientDash key.

- Local: `http://localhost:4322/#/campaign-deck`
- Published: https://chatgptricks.github.io/sentient-2.0/#/campaign-deck

`campaign-deck.mjs` owns content; `player.mjs` owns rendering and navigation; `fit.mjs` owns responsive fitting. Rebuild and reload after edits using `npm run build` from `site/`. Run `npm run check` before publishing. A push to `main` deploys through the existing GitHub Pages workflow.

The `#/…` hash namespace selects a deck from `registry.mjs`. Crossing between the normal website and the presentation reloads the document so each starts with its own styles and behavior. Public builds use `BASE_PATH=/sentient-2.0 STATIC_HOSTING=1 npm run build`.

## Deck Studio

`#/studio` is a simplified Canva for decks like this one (local: `http://localhost:4322/#/studio`, published: https://chatgptricks.github.io/sentient-2.0/#/studio). Everything in the campaign deck is available in it:

- **Templates** — each of the sixteen campaign slides (cover, reach metric, accounts, founders, approach, selection funnel, comparison, big words, promotional posts, process, CPM commitment, questions, equation, loop, closing proposal, closing logo), plus a blank slide. A template is inserted after the current slide with the campaign copy as a starting point.
- **Elements** — the slides' compositions as blocks that can be added to any slide and stacked: statement, paragraph, tags, bulleted list, metric with tags, large metric, commitment, arrow steps, funnel, comparison, big words, timeline, numbered cards, equation, loop, accounts, promotional posts, people (cut-out portraits on the lime circle) and image. Repeatable items (steps, filters, accounts, posts…) are added, removed and reordered in the inspector, within each element's limits.
- **Surfaces** — any slide except the cover and closing logo can use the dark, paper or lime surface; elements keep their contrast on each (`blocks.css`).

Text is edited directly on the slide or in the inspector; images are uploaded (resized to WebP), linked, or chosen from the Sentient catalogue (account avatars, founders' portraits). Accounts can read their exact followers from SentientDash, and a pasted Instagram link fills a promotional post, cover included. Slides are added, duplicated, deleted and reordered by dragging; undo/redo, ⌘D (duplicate), Delete (remove the selected element) and the arrow keys work outside text fields.

The canvas and every thumbnail are the real presentation: `studio-frame.mjs` (a second build entry) renders the deck with `player.mjs`'s markup, the deck stylesheets and `fit.mjs` in a 1600×900 frame, so the studio shows exactly what viewers see. `blocks.mjs` owns the element library and templates; `studio.mjs` the editor.

Decks are saved as you work in this browser's IndexedDB (`studio-store.mjs`) and can be exported or imported as JSON. **Publicar** (with the deck editor password) uploads the deck's images to the deck Worker and publishes the deck under its slug; the link `#/<slug>` then opens on any device, and **Actualizar publicación** replaces it (a stale copy is refused unless you confirm). The studio home lists published decks, opens their links, edits a copy, and the publish dialog unpublishes. **Presentar** opens the local draft (`#/~<id>`) without publishing. The campaign deck keeps its own layouts and saved-edit field names; studio decks never use its shared-text editor.
